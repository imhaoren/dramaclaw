# 03 配置与环境变量

配置有四层，**优先级从低到高**。排障时先判断「这个值到底从哪一层来的」，比盲改 `.env` 有效得多。

## 1. 四层配置

| 层 | 位置 | 谁写 | 生效时机 | 典型内容 |
|---|---|---|---|---|
| L1 环境变量 | `.env` / 容器 env | 运维 | **进程启动** | 网关地址、目录、并发、签名密钥 |
| L2 用户运行设置 | `state/local/settings.db` | 前端「模型网关」页 | 部分即时（缓存失效），部分需重连 Agent | 网关模式、API Key、媒体模型映射 |
| L3 项目配置 | `state/<user>/<project>/project_config.json` | 前端项目设置 / `project_config.py` | 下一个任务 | 风格预设、旁白、模型选择、知识管线 |
| L4 前端外观 | `frontend/src/index.css` + `/api/v1/config` | 开发者 | HMR / 刷新 | 主题色、品牌、功能开关 |

覆盖关系有一处反直觉：**L2 可以覆盖 L1 的模型网关配置**。CE 下 `model_gateway_settings.get_effective_newapi_config()` 先读 `settings.db`，没有再回落到 `.env`。所以「`.env` 里明明配了 key 却不生效」通常是前端保存过一次空配置。清理方式见 [14 §3](14-常见问题.md)。

## 2. `.env` 的 11 个分组

`.env.example` 按「谁消费」分组，不是按功能模块：

| 组 | 代表变量 | 说明 | 必填 |
|---|---|---|---|
| 0 任务信封签名 | `ST_TASK_ENVELOPE_ACTIVE_KEY_ID`<br/>`ST_TASK_ENVELOPE_KEYRING_B64_JSON` | 任务投递的签名与验签。**单机留空即可**，留空时走本地生成的密钥 | 否 |
| 1 NewAPI 网关 | `NEWAPI_BASE_URL`<br/>`NEWAPI_PROVISIONER_ENABLED`<br/>`NEWAPI_ADMIN_BASE_URL`<br/>`DRAMACLAW_IMAGE_PREFIX`<br/>`DRAMACLAW_VERSION` | 网关地址、自动建渠道开关、镜像前缀与版本 | 是（地址） |
| 2 参考媒体 relay | `MEDIA_RELAY_PROVIDER`<br/>`OSS_RELAY_*` / `S3_RELAY_*` / `CLOUDINARY_RELAY_*`<br/>`MEDIA_RELAY_TTL_SECONDS` | 把本地图片变成模型可访问的临时 URL。三选一 | 生成图片时必需 |
| 3 Cognee 图谱 | `COGNEE_LLM_MODEL`<br/>`COGNEE_EMBEDDING_MODEL` / `_DIM`<br/>`COGNEE_LLM_CONCURRENCY`<br/>`EMBEDDING_BATCH_SIZE` | 仅 `cognee_legacy` 管线需要；`structured_v1` 项目不用图谱 | 旧项目必需 |
| 4 文本模型 | 约 25 个 `*_MODEL` | 每个 Agent 一个模型变量，见 §3 | 是 |
| 5 图片模型 | `NEWAPI_IMAGE_MODEL`<br/>`NEWAPI_NANOBANANA2_MODEL`<br/>`DEFAULT_*_IMAGE_SELECTION`<br/>`PROP_REF_IMAGE_*` / `SCENE_*_IMAGE_*` | 各资产类型默认用哪个图模 | 是 |
| 6 图像基础参数 | `IMAGE_DEFAULT_WIDTH` / `_HEIGHT` / `_STYLE` | 兜底尺寸 | 否 |
| 7 视频模型 | `VIDEO_BACKEND`<br/>`NEWAPI_VIDEO_MODEL` / `_MODELS`<br/>`NEWAPI_VIDEO_RESOLUTION`<br/>`NEWAPI_VIDEO_DURATION_BOUNDS` | 视频后端选择与约束 | 是 |
| 8 音频模型 | `INDEXTTS2_PROVIDER`<br/>`INDEXTTS2_NEWAPI_MODEL`<br/>`NEWAPI_VIDEO_AUDIO_MODELS` | TTS / 对白音频 | 是 |
| 9 视频基础参数 | `VIDEO_FPS` / `_WIDTH` / `_HEIGHT` / `_CODEC` / `_BITRATE` | 合成参数 | 否 |
| 10 UI | `DIRECTOR_VIEWER_URL`<br/>`PROMPT_EXPORT_PASSWORD`<br/>`RELEASE_NOTIFICATIONS_ENABLED`<br/>`ST_WORKFLOW_RUN_STALE_SECONDS`<br/>`ST_WORKFLOW_READ_WORKERS` | 前端行为与工作流读超时 | 否 |
| 11 数据目录 | `NOVELVIDEO_DATA_ROOT`<br/>`NOVELVIDEO_OUTPUT_DIR` / `_STATE_DIR` / `_RUNTIME_DIR` | 三类目录，默认基于 `DATA_ROOT` | 否（有默认） |

另有不在 `.env.example` 但代码会读的关键变量：

| 变量 | 作用 | 备注 |
|---|---|---|
| `ST_EDITION` | `ce` / `ee` | 不设时：有 `ST_CONTROL_PLANE_DSN` 即 ee，否则 ce |
| `ST_CONTROL_PLANE_DSN` | 控制面数据库 | 设了就必须注册全部 18 个端口，否则启动失败 |
| `ST_TASK_BACKEND` | `celery`（默认）/ inline | CE 单机实际走 `InlineTaskBackend` |
| `ST_COOKIE_SECURE` | 会话 Cookie 是否 Secure | **默认 true**；本地 http 调试必须设 `0` |
| `ST_CE_ENABLE_ASSISTANT_SURFACES` | 外部虾导/画布内虾导开关 | CE 默认开 |
| `DRAMACLAW_CHAT_BACKEND` | `claude` / `codex` / `hermes` | 决定加载哪个 SDK 适配器 |
| `CODEX_BIN` / `CODEX_MODEL` / `CODEX_REASONING_EFFORT` | Codex 运行时 | 必须用带补丁的二进制，见 [13 §5](13-安装部署与运行.md) |
| `BRAINCLAW_*` | 网关遥测与控制上下文签名 | 未接网关时可全部留空 |

## 3. 模型变量与 Agent 的对应

模型变量是**按 Agent 分工**命名，而不是按模态。改之前先确认这个 Agent 属于哪条链路：

| 变量 | 消费方 | 链路 |
|---|---|---|
| `COGNEE_LLM_MODEL` | `cognee/config.py` | 图谱抽取、摘要（仅 legacy） |
| `LITERAL_BEAT_META_MODEL` | `workflows/literal_script_writing.py` | 剧本逐行切 beat（主线默认） |
| `CHARACTER_BUILD_MODEL` / `SCENE_BUILD_MODEL` | `structured_builders.py` | 资产构建 |
| `EPISODE_SCENE_PLANNER_MODEL` / `EPISODE_PROP_PLANNER_MODEL` | `agents/asset_compiler.py` | 单集场景/道具菜单 |
| `IDENTITY_PLANNER_*_MODEL`（3 个） | `agents/identity_planner.py` | 选角 / 分析 / 外貌描述，三段可分别换模型 |
| `GLOBAL_VIDEO_OPTIMIZER_MODEL` / `GLOBAL_VIDEO_IDENTITY_DETECTOR_MODEL` | `agents/global_video_optimizer.py` | 整集视频提示词优化 |
| `KEYFRAME_PROMPT_MODEL` | `agents/keyframe_prompt_builder.py` | 首尾帧过渡提示词 |
| `SEEDANCE2_PROMPT_COMPOSER_MODEL` | `seedance2_i2v/prompt.py` | Seedance 2.0 提示词组装 |
| `FREEZONE_TRANSLATION_MODEL` / `_TEXT_WRITER_MODEL` / `_STORY_SCRIPT_MODEL` / `_RECIPE_COMPILER_MODEL` / `_VISION_MODEL` | `freezone/*_node.py` | 画布节点 |
| `SCREENPLAY_NORMALIZER_MODEL` / `EPISODE_SCENE_RECONCILE_MODEL` / `NARRATED_SCENE_ASSET_MODEL` / `STAGING_PROP_MODEL` | 剧本规范化与 3GS 摆位 | 前处理 |
| `STYLE_ANALYZER_MODEL` / `CONTENT_REWRITER_MODEL` | 风格分析、内容改写 | 辅助 |
| `NEWAPI_IMAGE_MODEL` / `NEWAPI_NANOBANANA2_MODEL` | `generators/nanobanana_*.py` | 图像 |
| `NEWAPI_VIDEO_MODEL(S)` / `NEWAPI_VIDEO_AUDIO_MODELS` | `generators/video_generator.py` | 视频 |
| `INDEXTTS2_NEWAPI_MODEL` | `generators/indextts2_fal.py` | 语音 |

**共性约定**：所有 `*_MODEL` 填的是 **NewAPI 的逻辑模型名**，不是上游厂商原名。上游映射在网关侧配置，CE 不感知。

## 4. 改了要重启什么

| 改动 | 需要重启 | 原因 |
|---|---|---|
| `.env` 任意项 | API + 任务进程 | 配置在 import 期读入（`config.py` 模块级常量） |
| `settings.db`（前端保存） | 不重启，但**进行中的 Agent 会话需重开** | `model_gateway_runtime.refresh_model_gateway_runtime()` 让出网请求重读；Hermes worker 的网关指纹变了会被判定不可复用 |
| `project_config.json` | 不重启 | 每次任务读一次 |
| 新增/改名模型变量 | API + worker | `config.get_pydantic_model()` 首次调用时缓存 |
| 前端 `index.css` | 不重启（HMR） | — |
| 升级 `pyproject.toml` 依赖 | 重建镜像 / 重装 venv | 见 §5 |

## 5. 六个「别顺手升级」的版本锁定

这些锁定在代码里有注释说明，不是忘记解 pin：

| 依赖 | 锁定值 | 升了会怎样 |
|---|---|---|
| `pydantic-ai-slim` | `==1.107.0` | 2.x 移除 `Agent(output_retries=...)`，所有 planner/verifier 构造即 `TypeError` |
| `cognee` | `==1.0.5` | 内部 API 变动会破坏 `cognee/ladybug_access.py` 的猴补丁，图谱读写直接崩 |
| `numpy` | `<2.0.0` | Cognee 依赖链仍用 1.x ABI，2.x 会 `_ARRAY_API not found` |
| `click` | `<8.2.0` | Typer 旧版本的参数解析在 8.2 变更后报 `unexpected keyword` |
| `websockets` | `>=15,<16` | 16 改了握手 API，SSE/WS 桥接层异常 |
| `openai-codex` | git commit `25b5957` | SDK 自带二进制缺少网关需要的补丁；必须配 `CODEX_BIN` 指向补丁版 |

## 6. 配置自检

```bash
# .env ↔ 代码读取点 ↔ 文档 三方一致性
uv run python scripts/check_env_config.py

# 前端 i18n 与后端消息一致性（配置类文案常被漏改）
uv run python scripts/check_backend_i18n.py
```

`check_env_config.py` 会报三类问题：代码读了但 `.env.example` 没写、`.env.example` 写了但没人读、文档表格与实际变量名不符。CI 里是硬门禁。

## 7. 目录与端口约定

| 项 | 默认 | 变量 |
|---|---|---|
| 数据根 | 仓库根 `.` | `NOVELVIDEO_DATA_ROOT` |
| 产物 | `$ROOT/output` | `NOVELVIDEO_OUTPUT_DIR` |
| 状态 | `$ROOT/state` | `NOVELVIDEO_STATE_DIR` |
| 临时 | `$ROOT/runtime` | `NOVELVIDEO_RUNTIME_DIR` |
| API | `:8780`（`scripts/start-ce.sh` 默认） | `NOVELVIDEO_API_PORT` |
| 前端 dev | `:5173`（`VITE_API_URL` 指向 API） | `SUPERTALE_FE_PORT` / `frontend/.env` |
| NewAPI | `:3000` | `ST_NEWAPI_PORT` |

路径一律绝对化（`os.path.abspath`），因为 worker 的工作目录与 API 可能不同。

## 8. 四个高频误配

1. **`MEDIA_RELAY_PROVIDER` 没配**：图模调用返回 `MediaStorageUnavailable`。它决定「本地图怎么给模型看」，与 OSS 备份是两套配置。
2. **`ST_COOKIE_SECURE` 默认 true 却在 http 下调试**：登录成功但会话不保持（浏览器丢弃 Secure Cookie），必须显式设 `0`。
3. **`COGNEE_EMBEDDING_DIM` 与已有项目不一致**：旧项目在 `project_config.json` 里记了维度，改全局值不会迁移，检索结果全空。改维度等于换模型，要重建图谱。
4. **`NEWAPI_BASE_URL` 带 `/v1`**：网关地址应到端口为止；带 `/v1` 会拼成 `/v1/v1/chat/completions`，报 404 而非鉴权错，容易误判成 key 问题。
