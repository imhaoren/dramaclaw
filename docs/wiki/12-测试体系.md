# 12 测试体系

468 个测试 `.py`，435 个在 `tests/` 根目录平铺。看着乱，其实按前缀就能定位。这一篇给你一张地图，以及「改了 X 该跑哪几个」的对应关系。

## 1. 目录结构

| 位置 | 文件数 | 定位 |
|---|---:|---|
| `tests/test_*.py` | 435 | 主体：按功能点平铺，一个文件测一件事 |
| `tests/contract/` | 13 | **跨模块契约**：路由形状、任务完成、端口闭合 |
| `tests/ports/` | 19 | 端口实现的行为一致性（CE 本地实现） |
| `tests/support/` | 2 | 测试夹具与共享工具 |
| `tests/compliance/` | 1 | 合规检查 |
| `tests/data/` | 1 | 测试数据 |
| `tests/fixtures/` | 1 | 静态夹具体 |
| `tests/*.sh` + `sandbox_*.py` | 3 | 沙箱冒烟（Linux seatbelt 隔离） |

## 3. 四类测试的职责

### 3.1 契约测试（`tests/contract/`）

最重要的一类。它锁的是**接口形状**，不是实现细节：

| 文件 | 锁什么 |
|---|---|
| `test_m01_auth.py` | 认证与 scope |
| `test_m02_projects.py` | 项目 CRUD 路径与载荷 |
| `test_m03_episodes_scripts_content.py` | 分集/剧本/原文三组端点 |
| `test_m03_task_completion.py` | 任务从投递到完成的状态流转 |
| `test_m04_route_contracts.py` ~ `test_m09_route_contracts.py` | 按里程碑分组的全量路由契约 |
| `test_m07_tasks.py` | 任务查询/取消/流 |
| `test_m08_chat_agent.py` | 对话事件与工具回执 |
| `test_l014_inline_task_backend_concurrency.py` | inline 后端的并发上限 |

改路由**必须**同步改这里的期望，否则 CI 红。反过来说：这里的断言就是「API 不能随便改」的清单。

### 3.2 端口测试（`tests/ports/`）

验证 CE 本地实现满足端口契约：`test_auth_local`、`test_project_access`、`test_egress_operations`、`test_credit_quote`、`test_usage_noop` 等。

意义在于：EE 实现要能替换这些而不改调用方。所以端口测试只测**契约行为**（返回什么、抛什么），不测存储细节。

### 3.3 单元/集成测试（`tests/` 根目录）

一个文件聚焦一件事，命名即文档：`test_freezone_canvas_save_conflict.py` 就是「并发保存要报冲突」。这类测试通常直接调模块函数，不经过 HTTP。

### 3.4 沙箱与合规（`sandbox_*.sh`、`tests/compliance/`）

- `sandbox_linux_check.sh` / `sandbox_smoke.sh`：验证 seatbelt/隔离策略确实生效；
- `tests/compliance/`：许可证与禁用依赖检查。

## 4. 「我改了 X，该跑什么」

| 改动位置 | 最小测试集 |
|---|---|
| `api/routes/*.py` | `pytest tests/contract -k "m0"` + 对应 `tests/test_api_*.py` |
| `task_backend/` | `pytest tests/test_task_*.py tests/contract/test_m03_task_completion.py` |
| `freezone/` | `pytest tests/test_freezone_*.py tests/test_workflow_*.py` |
| `chat/` | `pytest tests/test_chat_*.py tests/test_hermes_*.py` |
| `ports/` 或 `ports/local/` | `pytest tests/ports` |
| `generators/` | `pytest tests/test_render_*.py tests/test_video_*.py tests/test_seedance2_*.py` |
| `verification/` | `pytest tests/test_verify_*.py tests/test_verification_*.py` |
| `utils/` | `pytest tests/test_*_utils.py tests/test_media_*.py` |
| 新增端点 | 先写 `tests/contract/` 用例，再写实现 |

全量跑：

```bash
uv run pytest -q                    # 全量
uv run pytest tests/contract -q     # 只跑契约
uv run pytest -q -x -k freezone     # 失败即停
uv run pytest --collect-only -q | tail -1   # 看用例总数
```

## 5. 端点覆盖率统计

`shared/api_coverage.py` 提供了一个运行期中间件 + pytest 钩子，能在跑测试时记录「哪些端点被真实调用过」：

- `mount_api_coverage_middleware()`：在 ASGI 层记录；
- `install_testclient_api_coverage_patch()`：接管 TestClient；
- `install_httpx_asgi_transport_api_coverage_patch()`：接管 httpx ASGI transport。

配合 `scripts/acceptance/` 使用，产出「387 个端点里哪些还没被覆盖」。这比行覆盖率有用得多——它衡量的是**接口是否有人走过**。

## 6. 测试环境的三个约定

1. **不碰真实 `state/`**。夹具用 `tmp_path` 造项目目录，`NOVELVIDEO_STATE_DIR` 在 conftest 里重定向。
2. **不打真实模型**。所有 provider 调用要么 mock，要么用 `MockVideoGenerator` / `MockImageGenerator` / `MockTTSGenerator`。
3. **不依赖顺序**。共享库（`_shared/`）相关测试必须显式建临时库，避免互相污染。

## 7. 写新测试的最短路径

```python
# tests/test_<域>_<行为>.py
async def test_canvas_save_rejects_empty_overwrite(tmp_project):
    """空画布覆盖非空画布必须报错，而不是静默清空。"""
    ...
```

三条命名规则，让后来者不用读代码：

- 文件名：`test_<域>_<行为>.py`；
- 函数名：完整的英文断言句（`test_save_conflict_when_revision_stale`）；
- docstring：一句中文说清「为什么这条规则存在」。
