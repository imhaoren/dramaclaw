# 14 常见问题

按「你看到的现象」索引。每条给：判定方法 → 根因 → 处理。带 `代码标识` 的可以在源码里直接 `grep` 到。

## 1. 先做这三件事

排障顺序很重要，上来就翻日志通常浪费半小时：

1. **确认进程还活着且是同一份配置**：`curl -fsS localhost:8780/api/v1/config`。
2. **确认问题在哪个阶段**：读接口挂了 / 任务不动 / 任务失败 / 产物不对。四类的排查路径完全不同。
3. **拿到 task_key**：所有生成类问题都能落到 `task_states` 一行上，`error` 与 `result_json` 就是答案。

## 2. 启动与安装

| 现象 | 判定 | 根因 / 处理 |
|---|---|---|
| `uv: command not found` | 缺包管理器 | 装 `uv`；`start-ce.sh` 会直接退出 2 |
| `pnpm is required` | 缺前端包管理器 | `corepack enable && corepack prepare pnpm@11.5.0 --activate` |
| 启动后 API 90s 未就绪 | 脚本超时退出 1 | 手动 `uv run --no-sync novelvideo api` 看真实报错；常见是依赖没同步完或端口被占 |
| `Address already in use` | 端口冲突 | `lsof -i :8780`；或改 `NOVELVIDEO_API_PORT` |
| 提示 `DRAMACLAW_CHAT_BACKEND` 不对 | 启动器只支持 codex | 在 `.env` 里改成 `codex`，或不用 `start-ce.sh` 自己起 |
| `RuntimeError: ST_CONTROL_PLANE_DSN 已设置但 EE 端口不完整` | 配了 EE DSN 却没装控制面 | CE 部署把 `ST_CONTROL_PLANE_DSN` 清空（`start-ce.sh` 会自动清） |
| `uv build` 失败，报缺许可证 | 缺 `LICENSES/` | 源码快照不完整，补许可证或不要 build |
| `docker compose` 找不到配置文件 | 缺 compose | 见 [13 §2.3](13-安装部署与运行.md) 三条替代 |
| `ffmpeg not found` 警告 | 未安装 | 合成/转码会失败；装上并确保在 `PATH` |

## 3. 登录与鉴权

| 现象 | 判定 | 根因 / 处理 |
|---|---|---|
| 登录成功但立刻退出登录 | 浏览器丢弃 Cookie | 本地 http 下 `ST_COOKIE_SECURE` 默认 `1`，设 `0` |
| 401 但 Cookie 看起来有 | 会话已过期 | 重新登录；Cookie 名是 `st_session` |
| `?token=` 传参无效 | 显式禁止 | 改用 `Authorization: Bearer`；查询参数凭据被拒（`UNSUPPORTED_QUERY_CREDENTIALS`） |
| Agent 调接口 403 | scope 不足 | 写操作需要 `projects:write` / `tasks:submit` 等精确 scope |
| 本地脚本调不通但 curl 可以 | 缺 `DRAMACLAW_LOCAL_AGENT_TRUST` | 仅在回环地址下开 `DRAMACLAW_LOCAL_AGENT_TRUST=1` |
| 换机器后所有人被登出 | 会话库不在 `state/` | 会话存于 `state/local`，迁移时要带上 |

## 4. 模型与网关

| 现象 | 判定 | 根因 / 处理 |
|---|---|---|
| 所有生成 502/504 | 网关不可达 | `curl $NEWAPI_BASE_URL/v1/models`；检查容器网络 |
| 404 而非 401 | `NEWAPI_BASE_URL` 带了 `/v1` | 地址只到端口，路径由客户端拼 |
| 401/403 | Key 错或渠道未配 | 前端「模型网关」页确认；CE 下 `settings.db` 覆盖 `.env` |
| 改了 `.env` 的 Key 不生效 | L2 覆盖 L1 | 前端保存过配置；清 `settings.db` 对应项或在前端重存 |
| `model_not_found` | 逻辑模型名与网关不一致 | 用网关暴露的**逻辑名**，不是上游原名 |
| `MediaStorageUnavailable` | 参考媒体上传未配置 | 配 `MEDIA_RELAY_PROVIDER` + 对应 OSS/S3/Cloudinary |
| `MediaRelayConfigError` | relay 配置不完整 | 三个 provider 只需配一个，但必填项要齐 |
| 生图报内容审核 | provider 拒绝 | 换提示词；`shared/provider_errors` 会归一化这类错误 |
| `InsufficientCreditsError` | 余额不足 | CE 下多为 NoOp 计量；EE 下需充值 |
| `BillingRuleNotConfiguredError` | 计费规则缺失 | 该功能未配价；EE 侧补规则 |

## 5. 任务不动了

按状态定位，**不要**先看日志：

| 状态 | 可能原因 | 处理 |
|---|---|---|
| `submitting` 长期不变 | 预留后投递失败 | 检查是否命中配额 429；重新提交一次（幂等键相同不会重复扣费） |
| `queued` 很久 | 泳道满 / 全局槽满 / 队列后端没消费 | 查 `GET /projects/{p}/tasks/limits`；inline 模式看进程是否卡死 |
| `running` 无进展 | 卡在外部 API / 子进程僵死 | 看 `logs_json` 最后一条；`ffmpeg`、3GS 构建看子进程是否存活 |
| `running` 且进程重启过 | 状态是孤儿 | 需要超时回收或手动置失败（[05 §8](05-任务系统.md)） |
| `failed` 但 `error` 为空 | runner 抛了未分类异常 | 看 `result_json` 与后端日志 |
| 前端一直"进行中" | 只订阅了 SSE 没取快照 | 先 `GET /tasks/{key}` 对齐 |
| 取消后仍完成 | 外部任务已提交，无法撤回 | 结果会被标记 `discarded`，属预期 |

配额相关错误标识：

| 错误 | 含义 |
|---|---|
| `ProjectTaskLimitExceeded` | 项目泳道满（默认 `default` 12 并发） |
| `ProjectUserTaskLimitExceeded` | 单用户在项目内超额（默认 3） |
| `GlobalLaneQueueLimitExceeded` | 全局排队超上限（默认 512） |
| `ChannelTaskLimitExceeded` / `UserTaskLimitExceeded` | 队列后端特有（EE） |

处理：等，或调对应 `ST_*_MAX_*` 环境变量（[05 §3](05-任务系统.md)）。**不要**靠重试轰炸，只会加深排队。

## 6. 画布

| 现象 | 标识 | 处理 |
|---|---|---|
| 保存 409 | `CanvasRevisionConflict` | 拉最新画布，前端合并后重存 |
| 保存 409 且载荷不同 | `CanvasIdempotencyConflict` | 换幂等键（说明重试逻辑有 bug） |
| 拒绝保存空画布 | `DangerousEmptyCanvasOverwrite` | 前端初始化失败，别强行覆盖 |
| 413 | 载荷超 5 MiB | 检查节点里是否塞了 base64 |
| 画布打不开 | `CanvasCorruptError` | 从 `_history/` 恢复上一版 |
| 整片媒体 403 | `CanvasMediaScopeError` | 画布引用了别的项目媒体；用跨项目粘贴（`asset_copy`） |
| 锁冲突 | `CanvasLockBusy` | 另一个写者持有锁；等或确认是否有僵死进程 |
| 提交回主线 422 | — | `PushTargetKind` 前后端不一致，或源文件不符合 slot 要求 |
| 保存后图片全裂 | — | 画布 URL 是旧项目域；跑 `canvas_static_urls` 迁移或重开项目 |

## 7. 对话与 Agent

| 现象 | 判定 | 处理 |
|---|---|---|
| 发消息无响应 | 上一回合锁未释放 | 等心跳超时；或 `interrupt_chat_turn` |
| 提示已有回合在跑 | 同作用域单并发 | 一个会话同时只能跑一个回合，等或中断 |
| `CodexRuntimeError` | `CODEX_BIN` 未配/非补丁版 | `bash scripts/setup-codex.sh` 后重启 |
| `HermesForkMissing` | 没装 fork | `bash scripts/setup-hermes.sh` |
| `HermesSessionUnavailableError` | 会话进程崩了 | 重开会话；连续出现看 `hermes_pool` 日志 |
| `HermesDrainingError` | 池正在回收 | 稍后重试 |
| `GatewayOriginMismatch` | 网关指纹变了 | 改网关配置后必须重开会话 |
| 工具调了但没效果 | 回执缺失 | 看 `chat_ui_events` 里的工具结果；画布操作要有 receipt |
| 改了模型但对话没变 | 池内连接复用 | 重开会话 |

## 8. 生成结果不对

| 现象 | 先查 | 处理 |
|---|---|---|
| 草图角色错/缺 | 角色颜色映射 | 重新 `assign_sketch_colors`；确认 `character_map` 覆盖本 beat |
| 渲染与草图差异大 | 首帧参考是否用了选中草图 | 重生成该 beat；检查 `selected_sketch` |
| 视频人物漂移 | 参考图是否含身份图 | 补身份图；Seedance2 用多参考 |
| 对白与口型不符 | 音频是否被复用 | 文本哈希变了但音频没重生成 → 清 `seedance2_voice_audio_records` 对应行 |
| 字幕对不上 | 音频时长变化 | 重新生成 SRT（时间轴按实际音频算） |
| 场景切换跳变 | 背景锚点未统一 | 给同场景 beats 设同一 `background_anchor` |
| 3GS 构建失败 | `Sharp3DUnavailable` / `BlockWorldUnavailable` | 缺可选依赖 `[world]` 或 Node 环境 |
| 全景接缝明显 | 重叠分析没跑 | 跑 `scene_overlap_analyzer` 后重生成 |

## 9. 数据与文件

| 现象 | 根因 | 处理 |
|---|---|---|
| 图片/视频 404 | 路径由 DB 记录硬编码了旧目录 | 路径应实时计算；检查是否手工改过 DB |
| 项目搬目录后全失效 | 同上 | 用 `ProjectPaths` 迁移，不要只 `mv` |
| `ProjectStorageOwnershipError` | 路径归属校验失败 | 说明 DB 记录的目录不属于该项目；核对 `projects` 表 |
| `UploadTooLargeError` | 上传超限 | 调 Nginx `client_max_body_size` 与后端限制 |
| `DocumentParseError` | 文档解析失败 | 确认编码/格式；转成纯文本再传 |
| `NovelImportRequiredError` | 未导入就点后续步骤 | 先完成 ingest |
| 数据库锁等待 | 有长事务/未 checkpoint | 减少并发写；确认 WAL 已启用 |
| 恢复后数据少一截 | 用了 `cp` 而非 `VACUUM INTO` | 重做快照流程 |

## 10. 前置条件类错误（都是「顺序错了」）

这些错误的共同点：不是 bug，是流程没走完。

| 错误 | 缺什么 | 正确顺序 |
|---|---|---|
| `NovelImportRequiredError` | 小说未导入 | 上传 → ingest |
| `IdentityCharactersRequiredError` | 角色未建 | 建角色 → 身份规划 |
| `IdentityPlanningPrerequisiteError` | 身份未规划 | 身份规划 → 资产图 |
| `ScenePlanningPrerequisiteError` | 场景未规划 | 场景菜单 → 场景母版 |
| `SceneCatalogBuildingError` | 场景目录构建中 | 等构建完成 |
| `SceneBuildNotApplicableError` | 当前管线不支持场景构建 | 确认 `knowledge_pipeline` |
| `ScenePlanningRunningError` | 已有规划任务在跑 | 等它结束 |
| `VideoPromptPrerequisiteError` | 缺视频提示词 | 先生成提示词 |
| `Seedance2VideoPrereqError` | 参考图/音频/时长不满足 | 按错误里的字段补齐 |
| `RenderIdentityDetectionRequired` | 渲染前未做身份检测 | 先跑 AI 身份检测 |
| `VoicePrerequisiteError` | 音色未就绪 | 先准备/选择音色 |
| `LabelsValidationError` | 草图编辑标签不合规 | 按 schema 修 `labels.jsonl` |

## 11. 性能

| 现象 | 原因 | 处理 |
|---|---|---|
| 画布卡顿 | 节点数过多、全量渲染 | LOD 已内置；减少同屏节点、收起分组 |
| 首屏慢 | 重页面没 `.lazy.tsx` | 改名加 `.lazy` |
| 视频阶段极慢 | `video` 泳道全局 2 槽 | 调 `ST_CE_GLOBAL_MAX_ACTIVE_VIDEO`，确认上游配额 |
| 列表页慢 | 大项目全量扫文件 | 用 `summary=true` 跳过文件探测 |
| 磁盘暴涨 | `runtime/` 与视频池未清 | 清 `runtime/`；按保留策略裁视频池 |

## 12. 还解决不了

按这个顺序收集信息，再去看代码：

1. `task_key` + `task_states` 整行（`sqlite3 state/.../data.db "select * from task_states where task_key='...'"`）；
2. `logs_json` 最后 20 条；
3. 相关表的实际行（`beats` / `canvas_command_messages` / `workflow_runs`）；
4. API 日志里同一时间窗的 traceback；
5. 若是 provider 问题，带上 provider 的 request id。

有这五项，绝大多数问题能在 10 分钟内定位到具体函数。
