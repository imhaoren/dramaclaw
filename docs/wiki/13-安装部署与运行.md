# 13 安装、部署与运行

## 1. 先看环境要求

| 项 | 要求 | 检查 |
|---|---|---|
| Python | `>=3.11,<3.13`（`pyproject.toml` 硬约束） | `python -V` |
| 包管理 | `uv` | `uv --version` |
| Node | 20.x | `node -v` |
| 前端包管理 | `pnpm` 11.5（`corepack enable` 后激活） | `pnpm -v` |
| FFmpeg | 任意近期版本，需在 `PATH` | `ffmpeg -version` |
| 模型网关 | 一个可达的 NewAPI 实例 + API Key | `curl $NEWAPI_BASE_URL/v1/models` |
| 磁盘 | 建议 ≥50 GB（视频很占空间） | `df -h` |
| GPU（可选） | 只有 3GS / SHARP / DA2 需要（`[world]` 依赖组） | `nvidia-smi` |

## 2. 三种启动方式

### 2.1 方式 A：`scripts/start-ce.sh`（推荐，唯一开箱可用）

```bash
bash scripts/start-ce.sh
# API:      http://127.0.0.1:8780/api/v1
# 前端:      http://127.0.0.1:5173
# 健康检查:  http://127.0.0.1:8780/api/v1/config
```

它会自动完成：复制 `.env`、强制 CE 模式、下载补丁版 Codex、`uv sync`、`pnpm install`、等待 API 就绪、同时托管两个进程。细节见 [11 §1](11-脚本运维与备份.md)。

### 2.2 方式 B：手动分步（想控制每个环节时）

```bash
# 1) 依赖
uv sync --group dev

# 2) 配置
cp .env.example .env
# 至少填：NEWAPI_BASE_URL、NEWAPI_API_KEY

# 3) 启动 API
uv run --no-sync novelvideo api --host 0.0.0.0 --port 8780

# 4) 另开终端起前端
cd frontend
cp .env.example .env        # 确认 VITE_API_URL=http://localhost:8780
pnpm install
pnpm dev --host 0.0.0.0 --port 5173
```

### 2.3 方式 C：Docker（本检出需要自己补 compose）

**注意**：本检出**不含** `docker-compose.yml` / `docker-compose.release.yml` / `LICENSES/`，README 里的 `docker compose up -d --build` 会失败。三条替代路径：

| 选择 | 做法 | 适用 |
|---|---|---|
| C1 本地跑 | 用方式 A 或 B | 开发、试用 |
| C2 自写 compose | 参考下方模板，只起 API + 前端 | 小规模部署 |
| C3 取完整发行包 | 从 release 页下载带 compose 与 LICENSES 的包 | 生产 |

自写 compose 的最小骨架（**示例，不是官方文件**）：

```yaml
services:
  api:
    build: .
    command: ["uv", "run", "--no-sync", "novelvideo", "api", "--host", "0.0.0.0", "--port", "8780"]
    environment:
      NOVELVIDEO_DATA_ROOT: /data
      NOVELVIDEO_STATE_DIR: /data/state
      NOVELVIDEO_OUTPUT_DIR: /data/output
      NOVELVIDEO_RUNTIME_DIR: /data/runtime
      ST_EDITION: ce
      NEWAPI_BASE_URL: http://newapi:3000
    volumes: ["/srv/dramaclaw:/data"]
    ports: ["8780:8780"]
  web:
    image: nginx:alpine
    volumes: ["./frontend/dist:/usr/share/nginx/html:ro"]
    ports: ["8080:80"]
```

`uv build` 在本检出会因缺 `LICENSES/` 失败；需要打 wheel 时先补许可证正文。

## 3. 首次配置模型

有两条路，选一条即可：

### 3.1 前端配置（推荐）

启动后打开 `http://localhost:5173` → 「模型网关」：

1. 选网关模式：**官方**（内置默认）/ **自定义**（自己的 NewAPI）/ **混合**；
2. 填 `NEWAPI_BASE_URL` 与 API Key（写入 `state/local/settings.db`，优先级高于 `.env`）；
3. 配置媒体模型映射（图片/视频/音频各用哪个逻辑模型）；
4. 保存后**重开对话会话**（网关指纹变了，旧 Hermes 连接会失效）。

### 3.2 `.env` 配置（适合容器/无 UI）

```bash
NEWAPI_BASE_URL=http://127.0.0.1:3000
NEWAPI_API_KEY=sk-xxxx
NEWAPI_IMAGE_MODEL=your-image-model
NEWAPI_VIDEO_MODEL=your-video-model
INDEXTTS2_NEWAPI_MODEL=your-tts-model
```

改完必须重启 API（配置在 import 期读入）。

## 4. 启动后的验证清单

按顺序做，每步都有明确预期：

| # | 检查 | 预期 |
|---|---|---|
| 1 | `curl -fsS localhost:8780/api/v1/config` | 返回 JSON（公开运行时配置） |
| 2 | 打开前端 `/login` | 能登录（首次可注册/本地账号） |
| 3 | `/` 项目列表 | 空列表不报错 |
| 4 | 新建项目 | 列表出现项目；`state/<user>/<project>/` 生成 |
| 5 | 上传一本小 txt → 启动导入 | 任务从 submitting → running → completed |
| 6 | 任务中心 `/projects/<p>/tasks` | 能看到任务与日志 |
| 7 | 生图试一次（画布或角色肖像） | 返回图片；`output/` 下有文件 |
| 8 | 生成 1 个 beat 的视频 | 需要网关视频模型可用 |

第 7 步失败最常见，先查 relay（参考媒体上传）配置，见 [03 §8](03-配置与环境变量.md)。

## 5. 生产部署要点

| 项 | 建议 | 原因 |
|---|---|---|
| 进程模型 | 单 worker 或换队列后端 | inline 任务后端的全局槽位是**进程内**的，多 worker 会让实际并发翻倍 |
| Web 服务器 | `gunicorn -k novelvideo.api.gunicorn_worker.GracefulUvicornWorker` | 普通 UvicornWorker 会硬杀进程，SSE 连接被截断 |
| Cookie | 生产保持 `ST_COOKIE_SECURE=1`（默认） | 防止管理员 Cookie 明文传输 |
| 反向代理 | Nginx 需关闭 SSE 缓冲：`proxy_buffering off`；`proxy_read_timeout` ≥ 300s | 否则任务进度"卡住" |
| 上传大小 | Nginx `client_max_body_size` ≥ 200m | 视频素材 |
| 数据目录 | `output/` 与 `state/` 挂持久卷 | 容器重建不丢数据 |
| 备份 | 每日 DB 快照 + 文件同步 | [11 §3](11-脚本运维与备份.md) |
| 时区 | 容器设 `TZ=Asia/Shanghai` | 日志与文件时间可读 |

**不要**把 `output/` 直接暴露成公共静态目录：媒体要走 `/static/projects/{project}/...`，它带项目级鉴权。

## 6. 停止与重启

```bash
# 方式 A：Ctrl-C 即可，脚本会同时回收 API 与前端
# 方式 B：找到进程
pkill -f "novelvideo api" ; pkill -f "vite"

# 确认端口释放
lsof -i :8780
```

重启前注意：正在跑的任务会停在 `running`，重启后需要超时回收或手动标失败（[14 §5](14-常见问题.md)）。

## 7. 升级

```bash
git fetch && git checkout <tag>
uv sync --group dev
(cd frontend && pnpm install && pnpm build)
# 重启
```

升级注意事项：

| 变化 | 需要做什么 |
|---|---|
| `pyproject.toml` 的 6 个锁定依赖 | **不要**自行放宽，见 [03 §5](03-配置与环境变量.md) |
| 新增环境变量 | 跑 `scripts/check_env_config.py` 对照 `.env.example` |
| schema 变更 | 首次启动会自动建表/加列；大改前先快照 |
| Workflow schema 变更 | 跑 `scripts/generate_workflow_contract.py` 重新生成前后端常量 |
| 前端分块变化 | 用户旧页面会触发一次自动刷新（`chunk-load-recovery`） |

回滚：代码回退 + 恢复对应时间的 DB 快照。**只回代码不回 DB** 可能因新列缺失报错（读取时缺列），所以两者要成对回滚。

## 8. 目录权限

| 目录 | 需要写权限的角色 |
|---|---|
| `state/`、`output/`、`runtime/` | API 进程用户 |
| `frontend/node_modules` | 构建用户 |
| 3GS 构建的临时目录 | 子进程用户（与 API 同用户最简单） |

容器里不要用 root 跑 API：Hermes/Codex 子进程会继承 UID，沙箱策略按 UID 生效。
