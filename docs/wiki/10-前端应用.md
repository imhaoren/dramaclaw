# 10 前端应用

前端 1,505 个 TS/TSX。其中 `features/` 占 544 个（画布域 382 个）、`__tests__/` 占 536 个、`components/` 187 个、`lib/` 123 个。这一篇解决三个问题：路由怎么对应到页面、画布那 382 个文件怎么分层、状态与任务流怎么串。

## 1. 技术栈与启动

| 项 | 选型 |
|---|---|
| 框架 | React 19 + TypeScript |
| 路由 | TanStack Router（文件式，`routes/` 目录即路由表） |
| 构建 | Vite（dev 代理 `/api` → `:8000`） |
| 样式 | Tailwind + 少量 CSS 变量（主题在 `index.css`） |
| 状态 | Zustand（`stores/`）+ 局部 React state |
| 数据 | 手写 fetch 封装（`api/client.ts`），无 React Query |
| 画布 | 自研（`features/canvas/`），非 React Flow |
| i18n | 自建（`i18n/index.ts` + `languages.ts`） |

```bash
cd frontend
npm ci
npm run dev      # http://localhost:5173
npm run build    # 产物在 dist/
```

## 3. 路由表

TanStack Router 用文件路径表达 URL，`_app` 是无路径的布局层（侧边栏 + 鉴权壳）：

| 文件 | URL | 页面 |
|---|---|---|
| `__root.tsx` | — | 根布局、错误边界、主题 |
| `_app.tsx` | — | 登录态守卫 + 全局导航 |
| `_app/index.tsx` | `/` | 项目列表（首页） |
| `_app/projects.$project/ingest.tsx` | `/projects/:project/ingest` | 上传与导入 |
| `_app/projects.$project/characters.lazy.tsx` | `/projects/:project/characters` | 角色与身份 |
| `_app/projects.$project/episodes.tsx` | `/projects/:project/episodes` | 分集列表 |
| `.../episodes.$episode/index.lazy.tsx` | `.../episodes/:episode` | 单集概览 |
| `.../script.lazy.tsx` | `.../script` | 剧本与 beats 编辑 |
| `.../sketches.lazy.tsx` | `.../sketches` | 草图工作台 |
| `.../beats.lazy.tsx` | `.../beats` | 渲染/首帧工作台 |
| `.../video.lazy.tsx` | `.../video` | 视频工作台 |
| `.../audio.lazy.tsx` | `.../audio` | 音频与配音 |
| `.../compose.lazy.tsx` | `.../compose` | 合成与导出 |
| `.../overview.lazy.tsx` | `.../overview` | 整集进度总览 |
| `.../freezone.lazy.tsx` | `.../freezone` | 画布 |
| `.../styles.tsx` | `.../styles` | 风格库 |
| `.../tasks.tsx` | `.../tasks` | 任务中心 |
| `.../assistant.tsx` | `.../assistant` | 对话助手 |
| `login.tsx` / `checkout.tsx` / `recharge.tsx` | `/login` 等 | 登录与支付 |

`.lazy.tsx` 后缀是 TanStack 的代码分割标记：这些页面单独打包，首屏不加载画布等重模块。**新增重页面时务必用 `.lazy.tsx`**，否则首包会显著变大。

## 4. 画布的 14 层

`features/canvas/` 不是一坨组件，而是有明确依赖方向的分层（内层不依赖外层）：

```text
domain/        22 种节点类型、注册表、纯规则        ← 无 React、无 IO
application/   用例编排：生成仲裁、保存协调、LOD      ← 依赖 domain
infrastructure/ 与后端/浏览器交互的适配
models/        数据模型与默认值
ui/            133 个浮层、面板、工具栏
nodes/         68 个节点组件（每个节点类型一组）
edges/         连线渲染与路由
tools/         画布工具（裁剪、标注、扩图等编辑器）
compose/       视频合成专用的时间线组件
snap-align/    对齐吸附算法
pricing/       积分显示
trackpad-pan/  触控板手势
ontology/      节点语义（哪些节点可连哪些）
```

| 层 | 文件数 | 代表文件 | 规则 |
|---|---:|---|---|
| `ui/` | 133 | `CanvasToolbar`、`NodeHeader`、`AssetLibraryModal` | 只做展示，不直接发请求 |
| `application/` | 94 | `canvasSaveCoordinator`、`generationTaskArbitration`、`canvasServices` | 用例层：可以有副作用，但不碰 DOM |
| `nodes/` | 68 | `ImageGenNode`、`VideoNode`、`AudioNode`、`SkillNode` | 每个节点一个目录，含表单与操作面板 |
| `domain/` | 34 | `canvasNodes`、`nodeRegistry`、`mainlineNodeTypes` | **纯函数**，最容易单测 |
| `hooks/` | 14 | `useCanvasSync`、`useNodeGenerationTaskState` | 画布内专用 hooks |

### 4.1 节点类型（22 种）

`domain/canvasNodes.ts` 的 `CANVAS_NODE_TYPES` 是唯一枚举：

| 类别 | 类型 |
|---|---|
| 输入 | `uploadNode`、`textAnnotationNode`、`scriptNode`、`beatContextNode`、`styleNode` |
| 图像 | `imageGenNode`、`imageNode`（编辑）、`vectorSvgNode`、`animatedGifNode`、`exportImageNode` |
| 视频 | `videoNode`、`videoStoryNode`、`videoComposeNode`、`videoBreakdownNode`、`storyboardNode`、`storyboardGenNode` |
| 音频 | `audioNode` |
| 3D/全景 | `pano360ViewerNode`、`threeDWorldNode` |
| 其他 | `groupNode`、`skillNode`、`htmlArtifactNode` |

### 4.2 提交落点（19 种）

`api/push.ts` 的 `PushTargetKind` 有 19 个值，对应后端 `freezone/slots.py` 的 22 个 Target（前端 19 是「可推送」的子集，3GS 的 5 个 PLY 落点由专用流程走）。**前后端这两个枚举必须同步改**，改一处不改另一处会 422。

## 5. 状态管理

13 个 Zustand store，按生命周期分三类：

| 类型 | store | 说明 |
|---|---|---|
| 全局长存 | `auth-store`、`themeStore`、`region-store`、`app-store` | 登录态、主题、区域、应用级开关 |
| 项目级 | `episode-workbench-store`、`project-nav-store`、`aspect-ratio-store` | 当前集、导航折叠、画幅 |
| 画布会话级 | `canvasStore`、`canvasPickStore`、`assetDropStore`、`referencePickStore`、`snapAlignStore`、`shotMetadataStore` | 画布内存态，刷新即失 |

规则：**服务端数据不进 store**。列表/详情每次进页面拉取，store 只放「UI 需要跨组件共享的临时状态」。例外是 `save-status-store`（保存状态）与 `seen-pool-store`（已看过的候选），它们本身是本地语义。

## 6. 任务中心

`task-center/` 11 个文件，是前端唯一允许「长连接 + 全局广播」的地方：

| 文件 | 职责 |
|---|---|
| `stream-client.ts` | SSE 连接、重连退避、事件解析 |
| `event-bus.ts` / `event-bus-context.ts` | 进程内事件总线（按 project/episode 分发） |
| `store.ts` | 任务快照缓存（按 task_key） |
| `provider.tsx` | React Provider，挂在 `_app` 层 |
| `matchers.ts` / `derivations.ts` | 事件 → UI 状态的匹配与派生 |
| `task-errors.ts` | 错误归一化（配额/上游/取消） |
| `use-task-activity.ts` / `use-task-subscribe.ts` | 组件订阅单个/一组任务 |

工作方式：先 `GET /tasks/{key}` 取快照，再订阅 SSE 增量；断线重连后重新取快照对齐。**不要**只靠 SSE 累积状态，事件会丢。

## 8. i18n

- 文案表在 `i18n/`（`index.ts` 装配，`languages.ts` 语言列表）；
- 后端返回 `LocalizableMessage`（key + 参数），前端负责翻译，见 [03 §2](03-配置与环境变量.md)；
- 两个校验脚本：`check_frontend_i18n.py`（前端硬编码文案）、`check_backend_i18n.py`（后端漏 key）；
- `scripts/frontend_i18n_allowlist.json` 里的条目是「确定不翻译」的白名单，新增需说明理由。

## 9. 组件约定

`components/` 187 个分两类，别混用：

| 类型 | 例子 | 规则 |
|---|---|---|
| UI 原语 | `button`、`dialog`、`input`、`tabs`、`sheet`、`tooltip` | 不含业务逻辑，可跨域复用 |
| 业务组件 | `beat-card`、`character-voice-panel`、`render-section`、`task-list` | 只服务一个域，优先放回 `features/` |

历史原因 `components/` 里仍有一批业务组件（如登录页的 12 屏滚动叙事 `FirstScreen…TwelfthScreen`、订阅支付组件），新代码不要再往这里加业务组件。

## 10. 四个关键机制

### 10.1 画布保存协调

`application/canvasSaveCoordinator.ts` 负责：

- 合并短时间内的多次改动（防抖）；
- 串行化保存（同一画布同时只有一个 in-flight 请求）；
- 冲突处理：收到 409 时不覆盖，提示用户或自动合并；
- 卸载/切页时强制 flush，避免丢最后一次修改。

自动保存暂停用 `canvasAutosaveHold.ts`（例如正在拖拽时）。

### 10.2 LOD（大画布性能）

节点数上百后，`canvasLod.ts` + `LodShellNode` 把远端节点降级为占位框，只渲染视口附近。视口外节点不挂图片、不跑动画。

### 10.3 分块加载失败恢复

`lib/chunk-load-recovery.ts`：Vite 分块 404（发版后旧页面）自动刷新一次，避免用户看到白屏。

### 10.4 区域与地区

`region-switch` / `region-tab-sync` / `region-abort`：多标签页下切换区域时，旧标签的请求会被 abort，避免串数据。

## 11. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 首屏很慢 | 新页面没用 `.lazy.tsx` | 改文件名加 `.lazy` |
| 画布改动丢失 | 保存协调被 `autosaveHold` 卡住且未 flush | 检查是否在拖拽态退出 |
| 保存报 409 | 多标签同时编辑同一画布 | 只留一个标签，或走冲突合并 |
| 任务永远「进行中」 | 只订阅 SSE 未取快照 | 按 [06 §4](06-HTTP-API参考.md) 先快照后订阅 |
| 文案显示 key | 后端新增了 key 前端没加 | 跑 `check_backend_i18n.py` |
| 提交回主线 422 | `PushTargetKind` 前后端不一致 | 同步 `api/push.ts` 与 `slots.py` |
