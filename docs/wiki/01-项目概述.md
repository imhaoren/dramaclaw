# 01 项目概述

## 1. 一句话定位

DramaClaw 是一条**小说/剧本 → 分集 → 分镜 → 图像 → 视频 → 成片**的工业化短剧生产线，开源版为 CE（Community Edition），以「本地可跑、自带模型网关、资产全落盘」为约束。

它的产出不是「一段 AI 视频」，而是**一部可交付的剧**：每集有剧本、有 beat、有草图、有首帧、有视频片段、有配音、有字幕、有合成成片，并且每个环节的产物都能被人工替换与返工。

## 2. 三个名字（新人最容易卡住的地方）

仓库里同时存在四套命名，指同一件事的不同层：

| 名字 | 出现位置 | 含义 |
|---|---|---|
| **DramaClaw** | README、Docker 镜像、用户界面、`DRAMACLAW_*` 变量 | 产品品牌名 |
| **supertale-ce** | `pyproject.toml` 的 `name`、发行包、`ST_*` 变量 | 发行包名；CE 表示社区版 |
| **novelvideo** | Python 包 `src/novelvideo/`、`NOVELVIDEO_*` 变量、`python -m novelvideo` | 代码包名（历史名，早期定位是「小说解说视频」） |
| **supertale-fe** | `frontend/package.json` | 前端包名 |

环境变量前缀同样并存：`ST_`（SuperTale）、`NOVELVIDEO_`、`DRAMACLAW_`、`NEWAPI_`、`OFFICIAL_`。**没有统一前缀是有意的**——变量按「谁消费」分组，见 [03 §2](03-配置与环境变量.md)。改名前请确认没有外部脚本依赖旧前缀。

## 3. 要解决的六个问题

| 问题 | 具体表现 | 项目里的对策 |
|---|---|---|
| 长文本一致性 | 30–60 集里角色外貌/服装/声音漂移 | 角色身份（identity）与参考图锁定 + 颜色标记 + 一致性校验（`verification/`） |
| 分镜不可控 | 文本生成视频「一次成型」，无法返工 | 先草图（sketch）后渲染（render）再视频，每层都可单独重生成 |
| 风格不可复用 | 每部剧重新调风格 | `styles/` 预设 + `StyleService` 单一事实源 + 风格模板库 |
| 资产散落 | 图片/视频/音频散在临时目录，路径写进数据库 | 路径由 `utils/path_resolver.py` **计算**而非存储；`state/` 与 `output/` 分离 |
| 任务丢失 | worker 退出后结果拿不到 | 任务状态持久化到 SQLite（`task_states`），五级配额与迟到订阅（[05](05-任务系统.md)） |
| 模型不可换 | 绑定单一厂商 | NewAPI 统一网关屏蔽上游差异；`ports/` 允许 EE 替换实现 |

## 4. 五条「有意不做」

读代码时会觉得「这里怎么缺一块」，多数是刻意取舍：

1. **不做多租户 SaaS 隔离**。CE 是单机部署，`ports/project.py` 里 `AllowAllProjectAccess` 直接放行；权限模型留给 EE。
2. **不做跨机分布式画布锁**。画布写入互斥用本机 `flock`（`freezone/canvas_lock.py`），只在单机成立；EE 通过 `ports/canvas_mutex.py` 换成分布式锁。
3. **不把生成的媒体二进制存进数据库**。SQLite 只存元数据与索引，文件在 `output/` 下按目录约定存放。
4. **不提供「一键重跑全剧」**。重跑粒度是 beat / 单集 / 单阶段，避免一次误操作烧掉全部配额。
5. **不在后端拼 UI**。NiceGUI 入口已废弃（`ui/__init__.py` 只留 `run_nicegui_app` 抛错），前端只认 React + REST/WebSocket。

## 5. CE 与 EE 的边界

CE 通过**端口（port）**把企业能力外置。判定方法：`src/novelvideo/ports/` 里定义的抽象，CE 在 `ports/local/` 给出本地实现；EE 覆盖注册即可替换。

| 能力 | CE 实现 | EE 语义 |
|---|---|---|
| 身份认证 | `ports/local/auth.py` 文件态会话 | 企业 SSO / OIDC |
| 项目权限 | `AllowAllProjectAccess` | RBAC + 组织隔离 |
| 计量与计费 | `NoOpUsageMeter` / `LocalCreditQuote` | 真实扣费与结算 |
| 审计 | `NoOpAuditSink` | 审计落库 |
| 任务投递 | `InlineTaskBackend`（同进程） | 队列 + 多 worker |
| 画布互斥 | 本机文件锁 | 分布式租约 |

18 个「EE 必需端口」的清单与判定见 [02 §5](02-架构与分层.md)。

## 6. 技术栈

| 层 | 选型 | 版本约束（不要随手升级） |
|---|---|---|
| Web 框架 | FastAPI + Uvicorn/Gunicorn | `fastapi>=0.128`，SSE 用 `sse-starlette` |
| Agent 框架 | PydanticAI | `pydantic-ai-slim==1.107.0`，**2.x 移除了 `output_retries` 参数** |
| 知识图谱 | Cognee + Ladybug | `cognee==1.0.5`，升级会破坏图访问补丁 |
| 任务 | Celery（EE / 多 worker）；CE 默认同进程 inline | `celery>=5.4` |
| 存储 | SQLite（项目态）+ 文件系统（媒体） | `numpy<2.0`（Cognee 依赖链） |
| 模型接入 | NewAPI 网关（文本 / 图像 / 视频 / 音频统一） | 模型名由 `official_defaults.py` 给默认值 |
| 前端 | React 19 + TanStack Router + Vite + Tailwind + Zustand | Node 20 |
| 画布 | 自研（`frontend/src/features/canvas/`，382 文件） | 无第三方画布库 |
| 3D | PlayCanvas + 3DGS（SHARP/DA2） | 可选依赖组 `[world]`，需 GPU |

版本锁定的坑集中在 [03 §5](03-配置与环境变量.md)，共 6 条，每条都附了「升了会怎样」。

## 8. 仓库的完整度（先看这里再动手）

本检出是**源码快照**，不是完整发行仓：

| 缺失 | 影响 |
|---|---|
| `docker-compose.yml` / `docker-compose.release.yml` | README 的 `docker compose up -d --build` 跑不通 |
