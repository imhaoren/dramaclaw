## 1. 这套文档有什么不同

第一版只写到「模块级」——知道 `api/routes/` 有 25 个路由文件，但不知道 `scenes.py` 里 24 个端点分别做什么、读哪张表、失败抛什么。第二版补上两层：

| 层级 | 载体 | 粒度 |
|---|---|---|
| **功能视角** | 本目录 `00`–`15` 篇 | 一条业务链路怎么走通：从上传小说到导出成片，从一次任务投递到状态落库 |
| **文件视角** | `files/` 下 11 篇 | 逐个文件：作用、关键实现、输入输出、依赖、使用场景、注意事项 |

两者互相引用，不重复叙述。

## 3. 三条推荐阅读路径

**A. 我要在 30 分钟内跑起来**
[13 安装部署](13-安装部署与运行.md) → [03 配置](03-配置与环境变量.md) → 跑 `scripts/start-ce.sh` → [14 常见问题](14-常见问题.md) 兜底。

**B. 我要加一个功能**
[02 架构](02-架构与分层.md) 认清「路由 → 任务 → runner → 生成器 → SQLite」这条主轴 → [05 任务系统](05-任务系统.md) 学会注册任务类型 → [06 API](06-HTTP-API参考.md) 找同类端点 → `files/03` 看该路由文件现有写法 → [12 测试](12-测试体系.md) 找契约测试模板。

**C. 线上出问题了**
[14 常见问题](14-常见问题.md) 按现象定位 → [05 §7](05-任务系统.md) 判断是排队、执行还是落库 → [04](04-数据模型与SQLite表.md) 查对应表是否写了 → [11](11-脚本运维与备份.md) 看日志与备份。

## 4. 文档约定

- **路径**：一律相对仓库根，如 `src/novelvideo/task_backend/runners/video.py`。
- **行数**：统计口径为 `wc -l`，含空行与注释，用于判断规模而非精确度量。
- **状态标记**（仅出现在 `files/` 条目里）：
  - `[核实]` 读过源码并逐条比对；
  - `[推断]` 依据函数签名/文档字符串/调用点推断，未逐行验证；
  - `[待补]` 代码本身缺少说明或需要运行期才能确认。
- **不写**：与代码重复的类型定义、可被 `git log` 替代的变更史。
- **链接**：所有站内链接均为相对路径；改动文档后请跑 [15 §4](15-维护与更新.md) 的链接校验脚本。
