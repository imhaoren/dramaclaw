# 05 · 安装与运行方式

> 三种运行形态：**Docker（推荐）**、**本地开发（热更新）**、**仅 API（无前端）**。
> 本篇所有命令均已在仓库内验证路径；标注 ⚠️ 的地方是本快照的实际情况，请先看。

---

## 1. 前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| Python | **3.11–3.12**（`>=3.11,<3.13`，3.13 不支持） | `python --version` |
| uv | 必需（依赖管理与运行） | `uv --version` |
| Node.js | 20+（Vite 6 要求 18+） | `node --version` |
| pnpm | **11.5.0**（`packageManager` 声明） | `pnpm --version` |
| ffmpeg | 必需，需含 `libx264` | `ffmpeg -version` |
| Docker | 仅容器方式需要，含 compose 插件 | `docker compose version` |
| 磁盘 | 几 GB（图片 + 生成媒体 + 状态） | — |
| 网络 | 出站可达模型网关（官方 `relayclaw.cdnfg.com` 或你自建/内置网关） | — |
| GPU | **不需要**（除非装 `world` extra 做 3DGS） | — |

**Windows 用户**：推荐 **Docker Desktop（WSL2 后端）** 或直接在 WSL2 里跑。原生 Windows 仅支持 Python 侧（`pywin32` 已按平台条件安装），`scripts/*.sh` 需要 bash 环境。

## 2. Docker 部署（两种模式）

### 2.0 先读：本检出缺少 compose 文件

当前仓库快照（commit `fa47fdc`）**不包含** `docker-compose.yml` 与 `docker-compose.release.yml`，也不含 `LICENSES/`。因此 README 里的：

```bash
docker compose up -d --build          # ❌ 本快照无法执行
```

**不可直接运行**。原因：这是一份**源码快照/拆分仓**，compose 编排与许可证正文留在完整发行仓。

**你的三个选择**：

| 选择 | 做法 |
|---|---|
| A. 用本地开发方式跑起来 | 直接跳到 [§3](#3-本地开发热更新)，无需 compose，功能等价（除 nginx/多容器编排） |
| B. 自己写一份 compose | 三个服务：`api`（Python，:8780）、`web`（nginx 伺服 `frontend/dist` 并反代，:8080）、`newapi`（可选网关，:3000）。数据卷挂到 `NOVELVIDEO_DATA_ROOT` |
| C. 取完整发行仓 | 从官方渠道获取完整 release 包（含 compose 与 LICENSES）后再按 README 执行 |

> 校验可用性：`ls docker-compose*.yml LICENSES/` 若报 not found，即确认缺失。

### 2.1 方式一：发布镜像（免构建）

适用：只想跑起来、不准备改代码。

```bash
cp .env.example .env
# 编辑 .env：把 PROMPT_EXPORT_PASSWORD 改成非默认值，并钉版本：
#   DRAMACLAW_VERSION=2.1.1
#   DRAMACLAW_GATEWAY_VERSION=v1.0.0-rc.24-dramaclaw.3

docker compose -f docker-compose.release.yml config --images   # 先确认要拉哪些镜像
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
docker compose -f docker-compose.release.yml ps                # api / newapi / web 均 running
```

要点：
- 此模式 **不要加 `--build`**。
- 不需要克隆网关源码。
- 国内拉取慢：`.env` 里设 `DRAMACLAW_IMAGE_PREFIX=claymore-registry.cn-chengdu.cr.aliyuncs.com/dramaclaw`，**三个版本变量要一起钉**（ACR 只有固定 tag，没有 latest）。

### 2.2 方式二：源码构建

适用：要改代码、自己维护分支。

```bash
# 网关必须与本仓并排（否则报 unable to prepare context）
git clone https://github.com/dramaclaw/dramaclaw-gateway.git ../dramaclaw-gateway

cp .env.example .env      # 至少改 PROMPT_EXPORT_PASSWORD
docker compose up -d --build
docker compose ps
```

三种重建粒度：

| 改了什么 | 重建命令 |
|---|---|
| 后端 + 前端 | `docker compose up -d --build api web` |
| 只改网关 | `docker compose up -d --build newapi` |
| 网关在别处 / 想让 Docker 自己拉 | `.env` 设 `DRAMACLAW_GATEWAY_SRC=/path/to/gateway` 或 `https://github.com/dramaclaw/dramaclaw-gateway.git#main` |

> 源码构建**没有热更新**，改代码必须重建容器。要热更新请用 §3。

### 2.3 两个模式共同的注意事项

| 项 | 说明 |
|---|---|
| 默认 Agent 后端 | 两种 compose 都默认 **Codex**（镜像内置凭据保护版 0.164.0）。若 shell 或 `.env` 里已有 `DRAMACLAW_CHAT_BACKEND`，会覆盖默认值 |
| 数据卷 | `ce-data`（容器内 `/data`）、`newapi-data`。`docker compose down` 保留卷，**加 `-v` 会删光** |
| 网关绑定 | 默认只绑 `127.0.0.1:3000`。需远程访问网关后台才设 `ST_NEWAPI_BIND=0.0.0.0` |
| 端口冲突 | 改 compose `ports` 左值，如 `8888:8780` |

## 3. 本地开发（热更新）

这是**当前快照唯一开箱可跑**的方式，也是日常开发推荐方式。

### 3.1 一键启动

```bash
git clone <本仓库>
cd dramaclaw

cp .env.example .env
# 至少检查：PROMPT_EXPORT_PASSWORD、CODEX_BIN（留空则自动下载）

scripts/start-ce.sh
```

`start-ce.sh` 做了这些事（读脚本可确认）：

1. 检查 `uv` / `pnpm` / `curl` 是否存在（缺则直接退出码 2）
2. `.env` 不存在则从 `.env.example` 复制
3. **强制** `ST_EDITION=ce`，并清空 `ST_CONTROL_PLANE_DSN` / `ST_REDIS_URL` / `ST_CELERY_*`
4. 统一 `NOVELVIDEO_*_DIR` 到仓库根（`state/`、`output/`、`runtime/`）
5. 校验 `DRAMACLAW_CHAT_BACKEND` **必须是 `codex`**（本启动器只装 Codex；其他后端会直接报错退出）
6. 调 `scripts/setup-codex.sh` 解析/下载 Codex 运行时，导出 `CODEX_BIN`
7. `uv sync --group dev`；`frontend/node_modules` 不存在则 `pnpm install`
8. 起 API（`uv run --no-sync novelvideo api`），**轮询 `/api/v1/config` 直到就绪**（默认 90s 超时）
9. 起 Vite dev server（:5173），Ctrl+C 同时收掉两个进程

打开 <http://localhost:5173>。

### 3.2 手动分步启动（便于调试）

```bash
# 1) 依赖
uv sync --group dev
cd frontend && pnpm install && cd ..

# 2) 环境变量（两种方式）
export ST_EDITION=ce
export NOVELVIDEO_API_URL=http://127.0.0.1:8780
export DRAMACLAW_API_URL="$NOVELVIDEO_API_URL"
export DRAMACLAW_CHAT_BACKEND=codex
export CODEX_BIN="$(bash scripts/setup-codex.sh)"

# 3) 起后端（热重载）
uv run novelvideo api --port 8780 --reload

# 4) 另开终端起前端
cd frontend && pnpm dev        # :5173，/api/v1 自动代理到 8780
```

`frontend/.env` 可覆盖接口地址：

```dotenv
VITE_API_URL=http://localhost:8780
# VITE_FREEZONE_URL=http://localhost:5176   # 画布独立应用（可选）
# VITE_EDITION=ce                            # 仅在 /api/v1/config 不可达时兜底
```

### 3.3 首次运行会发生什么

| 动作 | 位置 |
|---|---|
| 生成任务信封签名密钥 | `state/task_envelope_keyring.json` |
| 创建 SQLite（首次访问项目时） | `state/<user>/<project>/data.db` |
| 写 API 日志 | `runtime/api.log`（10 MB × 3 轮转） |
| 启动官方媒体模型目录轮询（仅 CE） | 后台任务，默认 300s |
| 恢复 Director Auto 未完成运行 | 失败仅警告，不阻塞启动 |

## 4. 仅 API 模式（无前端）

适合脚本化、CI、或自建前端。

```bash
uv sync --group dev
uv run novelvideo api --host 0.0.0.0 --port 8780
```

或者用生产 WSGI：

```bash
gunicorn -k uvicorn.workers.UvicornWorker novelvideo.api.wsgi:app -b 0.0.0.0:8780
```

> `api/wsgi.py` 的导入顺序是**刻意的**：必须先 `load_project_dotenv()` 再导入 `app`，所以该文件对 ruff 永久豁免 E402。别"顺手整理"这个导入顺序。

CORS/同源：CE 默认同源部署。前后端分域时需经反向代理聚合，或让前端走 `VITE_API_URL` + 代理（Vite dev 已配好）。

## 5. 首次配置模型（必做一次）

打开 UI → **设置 → 模型配置**，三选一：

| 模式 | 做法 | 适用 |
|---|---|---|
| **官方（推荐）** | 粘贴 DC key（<https://relayclaw.cdnfg.com> 获取）→ 保存并启用。地址已预填 `https://relayclaw.cdnfg.com/v1`，**无需任何模型映射** | 想立刻出片 |
| **自定义** | 一键初始化内置网关（`newapi`）→ 在网关后台加自己的上游渠道与模型映射 | 有自己的 key / 要用本地 ComfyUI |
| **本地 + 官方混合** | 主流水线用官方模型，额外渠道走内置网关 | 主流程稳、实验走本地 |

要点：
- 官方模式下 **内置网关保持闲置**，不消耗资源。
- 官方模式**不需要** `.env` 里配任何 key；地址与 token 都写进本机 `settings.db`。
- 自定义模式需内置网关在 `127.0.0.1:3000`，其 SQLite 为 `./state/newapi/one-api.db`（"初始化"按钮就写这里）。

## 6. 启动验证清单

按顺序打这几枪，能快速定位问题层级：

```bash
# 1) 进程活着
curl -s http://127.0.0.1:8780/healthz
# → {"status":"ok"}

# 2) API 装配完成、配置可读（这也是启动器的就绪探针）
curl -s http://127.0.0.1:8780/api/v1/config | head -c 400

# 3) 前端可达
curl -sI http://localhost:5173 | head -1        # 本地开发
curl -sI http://localhost:8080 | head -1        # Docker

# 4) 模型连通（在 UI 里发一次最小生成，或看任务中心错误）
```

| 现象 | 层级 | 去查 |
|---|---|---|
| `curl` 拒绝连接 | 进程/端口 | 端口占用、启动日志、`NOVELVIDEO_API_PORT` |
| `/healthz` 通但 `/api/v1/config` 500 | 启动钩子 | `runtime/api.log` 里的 startup 异常 |
| API 通但页面白屏 | 前端构建 | `DRAMACLAW_FRONTEND_DIST` 或 nginx；浏览器控制台 |
| 页面能开但生成全红 | 模型配置 | 设置 → 模型配置；网关可达性 |

## 7. 停止、数据与备份

```bash
# 本地开发：Ctrl+C 即可（启动器会收掉两个子进程）

# Docker
docker compose stop            # 停容器，保留卷
docker compose down            # 删容器，保留卷
docker compose down -v         # ⚠️ 连卷一起删 = 删库
```

**数据在哪**：

| 内容 | Docker | 本地开发 |
|---|---|---|
| 项目 DB / 设置 | 卷 `ce-data` → `/data/state` | `./state` |
| 产物 | 卷 `ce-data` → `/data/output` | `./output` |
| 网关 DB | 卷 `newapi-data` | `./state/newapi` |

**备份**：`novelvideo backup` 子命令（`backup/cli.py`），含每日 DB 快照（`db_daily.py`）、文件同步（`files_sync.py`）、WAL 迁移（`wal_migrator.py`）。

## 8. 升级

| 模式 | 命令 |
|---|---|
| 发布镜像 | 改 `.env` 里的 `DRAMACLAW_VERSION` / `DRAMACLAW_GATEWAY_VERSION` → `pull` → `up -d` |
| 源码构建 | `git -C ../dramaclaw-gateway pull && git pull && docker compose up -d --build` |

升级前：备份 `ce-data`；升级后：`docker compose ps` + `/api/v1/config` 探活。

## 9. 生产部署要点（自托管）

| 项 | 建议 |
|---|---|
| 反向代理 | nginx/OpenResty，`client_max_body_size` 至少匹配上传上限（见 `tests/test_openresty_upload_limit.py`） |
| 密钥 | `PROMPT_EXPORT_PASSWORD` 必改；不要提交 `.env`；`pre-commit` 的 gitleaks 会拦 |
| Cookie | HTTPS 部署保持 `ST_COOKIE_SECURE=true`；本机 HTTP 调试设 `0` |
| 沙箱 | 若用 Hermes 后端，Linux 需内核支持 unprivileged user namespaces；共享宿主必须按用户挂载数据卷后才能设 `SUPERTALE_LINUX_SANDBOX=1` |
| 单机假设 | CE 是单用户、单实例。多副本会踩任务信封 keyring 与 SQLite 写锁，**不要水平扩容**（那是 EE 的场景） |
| 资源 | 2 vCPU / 4 GB 起；磁盘按"每集素材量 × 集数"预留 |
