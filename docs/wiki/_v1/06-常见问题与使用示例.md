# 06 · 常见问题与使用示例

> 前半是排错手册，后半是可复制的用法示例。
> 排错的原则：**先定位层级，再查该层日志**——不要一上来就翻代码。

---

## 1. 排错方法论：先分层

| 层 | 症状 | 第一个动作 |
|---|---|---|
| L1 进程 | 端口连不上、容器退出 | `docker compose ps` / `docker compose logs api` / `runtime/api.log` |
| L2 装配 | `/healthz` 通但 `/api/v1/config` 报错 | 看启动钩子异常（lifecycle 端口、WAL 迁移、模型目录轮询） |
| L3 前端 | 页面白屏、入口 JS 404 | 浏览器 Console / Network；`DRAMACLAW_FRONTEND_DIST` 是否正确 |
| L4 模型 | 生成任务全红 | 设置 → 模型配置；网关可达性；任务详情里的错误码 |
| L5 媒体 | 合成阶段失败 | ffmpeg 是否存在、是否含 `libx264` |
| L6 数据 | 项目打不开、资产 404 | `data.db` 完整性；资产名是否含 `/` |

## 2. 常见问题（FAQ）

### 2.1 启动类

| 现象 | 原因 | 解决 |
|---|---|---|
| 容器起不来 / 立即退出 | 配置、端口或卷问题 | `docker compose logs api` 逐行看 |
| `8780` 端口被占用 | 本机已有进程 | 改 compose `ports` 左值（如 `8888:8780`），或 `lsof -i :8780` 停掉 |
| 健康检查一直 unhealthy | 探活打 `/api/v1/config`，API 自身在报错 | 看启动日志找真正异常，别只盯健康检查 |
| Python 版本报错 | 用了 3.13 或 3.10 | `uv python pin 3.12` 后 `uv sync` |
| `start-ce.sh` 退出码 2 | 缺 `uv`/`pnpm`/`curl`，或 `DRAMACLAW_CHAT_BACKEND` 不是 `codex` | 按提示装依赖；`.env` 里改回 `codex` |
| 启动报 `ST_CONTROL_PLANE_DSN 与 ST_EDITION=ce 同时设置` | 矛盾配置 | 二选一：CE 就清空 DSN |
| 启动报 `EE 端口不完整，缺失: ...` | 设了 DSN 但 EE 插件未注册 | CE 场景清空 DSN；EE 场景检查 entry point 组 |

### 2.2 模型 / 网关类

| 现象 | 原因 | 解决 |
|---|---|---|
| 模型调用全报错 | 渠道未配置或不可达 | 确认当前模式（官方/自定义）；官方查 DC key，本地查网关与 runtime token |
| 某环节报"模型不存在" | 网关无对应逻辑模型映射，或渠道未启用 | 在网关后台补映射；或切官方模式 |
| 结构化环节报 `Exceeded maximum output retries`，纯文本正常 | 上游没返回 function/tool call。做 Chat Completions 转换的中转站（Codex2API 类）已知会丢 `tool_calls` | 在内置 NewAPI 给该渠道开 **ChatCompletions → Responses Compatibility**（`chat_completions_to_responses_policy`），改走 `/v1/responses` |
| 文本超时 | 默认 120s 不够 | 调大 `NEWAPI_TEXT_TIMEOUT_SECONDS` |
| 内网网关被代理拦截 | `NEWAPI_TEXT_TRUST_ENV=true` 读了系统代理 | 设 `false` |
| 参考图功能不可用 | 未配 `OSS_RELAY_AK/SK` | 配 OSS 或 S3 relay；纯文本→成片流程可不配 |

### 2.3 媒体 / ffmpeg 类

| 现象 | 原因 | 解决 |
|---|---|---|
| 合成报找不到 ffmpeg | 本地开发未装（Docker 已内置） | 装 ffmpeg，或 `FFMPEG_PATH` 指定 |
| 合成报编码器不可用 | ffmpeg build 缺 `libx264` | 换含该编码器的 build，或改 `VIDEO_CODEC` |
| 成片黑屏 / 时长异常 | 前序图片/音频缺失 | 回看该集任务日志，确认素材已生成 |

### 2.4 数据 / 升级类

| 现象 | 原因 | 解决 |
|---|---|---|
| 重建后数据没了 | 用了 `docker compose down -v` | 卷被删。恢复备份；以后只用 `down`（不加 `-v`） |
| `unable to prepare context: path ".../dramaclaw-gateway" not found` | 源码构建要求网关并排 | `git clone https://github.com/dramaclaw/dramaclaw-gateway.git ../dramaclaw-gateway`，或设 `DRAMACLAW_GATEWAY_SRC` |
| 升级后报配置错误 | 版本不匹配 / 配置漂移 | 源码模式：先 pull 网关再 pull 主仓后重建；镜像模式：先改版本号再 pull |
| 资产接口 404（名字看着正常） | 名字里含 `/` 或纯 `.`（uvicorn 提前还原 `%2F`） | `uv run novelvideo repair-asset-names --user <u> --project <p>` |

### 2.5 开发 / 联调类

| 现象 | 原因 | 解决 |
|---|---|---|
| 本地 HTTP 登录后 cookie 没存住 | `ST_COOKIE_SECURE=true` | 设 `0`；Vite 代理也会改写 `Set-Cookie` 去掉 `Secure` |
| 前端能开但接口 401 | 前后端 cookie/域名不匹配 | 用 Vite 代理（同源），或统一反向代理 |
| 改了路由但页面 404 | 未重新生成路由树 | 重启 `pnpm dev` 让插件重生成 `routeTree.gen.ts`（**勿手改该文件**） |
| 前端样式改了但 `DESIGN.md` 检查失败 | 只改了 CSS 没同步规范 | 同 commit 更新 `DESIGN.md`，`npx @google/design.md lint DESIGN.md` 保持 0 error |
| `ruff` 报新增文件的 F401 | 门禁只管新增代码，存量有豁免基线 | 清理未用导入；**不要**往 `per-file-ignores` 里加新条目 |
| pytest 跑到 EE 测试失败 | 默认应排除 | 默认 `addopts` 已含 `-m 'not ee and not e2e'`；别手改配置 |

### 2.6 本快照专属问题

| 现象 | 说明 |
|---|---|
| `docker compose` 找不到配置文件 | 本检出不含 `docker-compose*.yml`，见 [05 §2.0](05-安装与运行方式.md#20-先读本检出缺少-compose-文件) |
| `uv build` 报找不到 `LICENSES/Elastic-2.0.txt` | 本检出缺 `LICENSES/` 目录；`pyproject.toml` 的 `license-files` 指向它 |
| `docs/compliance/` 不存在 | 同上，属完整发行仓内容 |
| `git log` 只有一个 commit | 本仓是 `dramaclaw init` 快照，非完整历史 |

### 2.7 Hermes / 3D world 类

| 现象 | 解决 |
|---|---|
| `DRAMACLAW_CHAT_BACKEND=hermes` 启动报不可用 | `uv tool install 'hermes-agent[acp]'`，再 `hermes doctor` 诊断 |
| Hermes 在旧内核上无法沙箱 | 单租户 CE 可设 `SUPERTALE_ALLOW_UNSANDBOXED=1` 降级（会大声告警）；EE/生产**必须**修内核 |
| 报 `FileNotFoundError` 指向 `BuilderGPT/...` | 重特性脚本不在精简包内；纯文本→成片不需要，走 3D 流程才需补齐 |
| `uv sync --extra world` 失败 | 必须用 uv（依赖 override 才生效）；GPU 加速需 CUDA |

## 3. 使用示例

### 3.1 REST API：从零到第一集剧本

> 完整字段以运行时 OpenAPI 为准：启动后端后访问 <http://localhost:8780/docs>。
> 下面只用到已确认的端点与字段。

```bash
API=http://127.0.0.1:8780/api/v1

# 0) 健康与配置
curl -s http://127.0.0.1:8780/healthz
curl -s "$API/config" | head -c 300

# 1) 创建项目（name ≤ 64 字符）
curl -s -X POST "$API/projects" \
  -H 'Content-Type: application/json' \
  -d '{"name":"my-first-drama"}'
# → {"ok":true,"data":{"id":"<project_id>","project_id":"<project_id>","name":"my-first-drama"}}

PROJECT=<project_id>

# 2) 上传原稿（multipart，字段名 file）
curl -s -X POST "$API/projects/$PROJECT/ingest/upload" \
  -F "file=@./novel.txt"

# 3) 启动摄取（filename 必须与上传后的文件名一致）
curl -s -X POST "$API/projects/$PROJECT/ingest/start" \
  -H 'Content-Type: application/json' \
  -d '{"filename":"novel.txt","rebuild":false,"spine_template":"drama"}'

# 4) 查摄取结果（角色 / 场次概览）
curl -s "$API/projects/$PROJECT/ingest/graph"

# 5) 看任务进度（也可用 SSE 订阅）
curl -s "$API/projects/$PROJECT/tasks"
curl -N "$API/projects/$PROJECT/tasks/stream"

# 6) 规划分集（请求体字段见 /docs）
curl -s -X POST "$API/projects/$PROJECT/episodes/plan" \
  -H 'Content-Type: application/json' -d '{}'

# 7) 列出剧集，取第一集
curl -s "$API/projects/$PROJECT/episodes"

# 8) 生成第 1 集剧本（异步任务，随后轮询 tasks）
curl -s -X POST "$API/projects/$PROJECT/episodes/1/script/generate" \
  -H 'Content-Type: application/json' -d '{}'

# 9) 读剧本 / 节拍
curl -s "$API/projects/$PROJECT/episodes/1/script"
curl -s "$API/projects/$PROJECT/episodes/1/beats"
```

**响应约定**：成功几乎都是 `{"ok": true, "data": ...}`；失败是 `{"ok": false, "error": "<中文可读>", "data": {...}}`。配额 429、额度 402、计费规则 409、授权 403 都带 `data.limit_scope` 等机器可读字段。

**取消一个任务**：

```bash
curl -X DELETE "$API/projects/$PROJECT/tasks/script_writer/1"
```

### 3.2 CLI

```bash
# 启动 API（CLI 里 ui 命令已废弃，会转发到 api）
uv run novelvideo api --port 8780 --reload

# 备份（子命令组）
uv run novelvideo backup --help

# 修资产名（先 dry-run 看影响，再加 --apply --yes）
uv run novelvideo repair-asset-names --user admin --project my-first-drama

# 迁移混入时间词的场景名（默认 dry-run，安全）
uv run novelvideo migrate-scene-names --user admin --project my-first-drama
uv run novelvideo migrate-scene-names --user admin --project my-first-drama --apply --yes

# 旧路径：Cognee 导入与查询
uv run novelvideo cognee-ingest --project my-first-drama --novel ./novel.txt
uv run novelvideo cognee-profile --project my-first-drama
uv run novelvideo cognee-search  --project my-first-drama --query "主角的师父是谁"
```

> 两个迁移命令都**默认 dry-run**，且 `--apply` 必须配 `--yes`。这是有意设计：它们会改 `data.db` 和资产目录。

### 3.3 接入外部 Agent（MCP）

仓库自带 MCP 声明 `.mcp.json`：

```json
{
  "mcpServers": {
    "dramaclaw": {
      "command": "uv",
      "args": ["run", "python", "-m", "novelvideo.chat.dramaclaw_mcp"],
      "env": {
        "DRAMACLAW_API_URL": "http://localhost:8780",
        "DRAMACLAW_CE_OWNER": "1"
      }
    }
  }
}
```

在 Codex / Claude Code / WorkBuddy 等 MCP 客户端中指向该配置即可。`DRAMACLAW_CE_OWNER=1` 表示以 CE 单用户身份操作（免 token，仅限本机）。

更多客户端的接入清单在 `agent-kit/`（含 `manifest.json`、`hosts/`、`skills/`）。

### 3.4 前端开发：三个必守约定

```bash
cd frontend
pnpm dev            # :5173
pnpm build          # 产物到 dist/
pnpm test           # vitest

# 视觉规范校验（0 error 是准入线）
npx @google/design.md lint ../../DESIGN.md
```

1. **颜色/圆角/间距/动效一律取 CSS 变量**（`src/index.css`），禁止写死 hex/px/ms。
2. **改 token 必须同 commit 改 `DESIGN.md`**，否则视为视觉回归。
3. **`src/routeTree.gen.ts` 是生成物**，改路由结构后由插件重新生成。

### 3.5 加一个新任务类型的骨架

```python
# src/novelvideo/task_backend/runners/my_feature.py
from novelvideo.task_backend.registry import register_project_task_runner


def _run_my_feature(payload, ctx):
    """返回 dict 即结果；抛异常即 failed。"""
    ...
    return {"ok": True, "artifacts": [...]}


register_project_task_runner(
    "my_feature",              # 任务类型名
    _run_my_feature,
    requires_home_node=True,   # 是否必须在家节点
    lane="default",            # default / video / world / ffmpeg
)
```

然后在 `runners/__init__.py` 里 import 该模块，并把类型名补进 [03 §3.1](03-核心功能与流程.md#31-任务类型清单28-种)。

**注意**：`lane` 拼错会**直接抛错**（`normalize_queue_kind` 拒绝未知 lane），不会静默落到 `default`。
