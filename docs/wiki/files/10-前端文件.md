## 1. 目录总览与分层

```
frontend/src/
├── main.tsx              # React 挂载入口
├── routeTree.gen.ts      # TanStack Router 自动生成（勿手改）
├── index.css             # Tailwind 入口 + 设计令牌
├── routes/               # 27  页面级路由（文件式）
├── features/             # 544 业务域（canvas 占大头）
├── components/           # 187 通用 UI
├── lib/                  # 123 纯逻辑
├── stores/               # 13  Zustand
├── api/                  # 12  后端调用
├── hooks/                # 21  复用 hook
├── task-center/          # 11  任务流
├── types/                # 15  TS 类型
├── pipeline-import/      # 7   导入流水线
├── i18n/  commands/  __mocks__/
└── __tests__/            # 536 测试
```

**依赖方向（单向，不许反向）** `[核实]`

```
routes/ ──► features/ ──► components/ ──► lib/ ──► types/
                │              │
                ├──► api/ ─────┤
                ├──► stores/ ──┤
                └──► task-center/
```

- `types/` 不 import 任何 `src/` 内模块（纯类型）。
- `lib/` 不 import `components/` 或 `features/`（纯逻辑，可单测）。
- `components/` 不 import `features/`（通用件不能反依赖业务）。
- `features/*` 之间**默认不互相 import**；跨域协作走 `lib/` 或 `api/`。

违反方向的典型症状：`lib/` 里出现 `import ... from '../features/canvas/...'` 会造成循环依赖与测试难写，CI 的 `lint_ce_imports.py` 不查前端，只能靠 review。

## 16. 命名约定与「不逐条写」的推断规则

`files/README.md` 说明本卷是「目录级 + 关键文件级」。未逐条列出的文件，可按以下约定定位，**这套约定在本仓库的遵守率很高** `[核实]`：

| 模式 | 含义 | 所在层 |
| --- | --- | --- |
| `XxxPanel.tsx` | 属性/参数面板，受控组件，数据由 props 注入 | `ui/`、`components/` |
| `XxxDialog.tsx` / `XxxModal.tsx` | 模态，含确认/取消，通常有 `open`/`onOpenChange` | `ui/`、`features/` |
| `XxxOverlay.tsx` | 画布上层浮层，绝对定位，不吃指针事件（除非激活） | `features/canvas/ui` |
| `XxxNode.tsx` | 画布节点渲染，必须接受 `NodeProps` | `features/canvas/nodes` |
| `XxxCard.tsx` / `XxxTile.tsx` | 列表项 | `components/` |
| `useXxx.ts` | hook，返回状态 + 动作 | `hooks/`、各 feature |
| `xxx-store.ts` | Zustand store | `stores/` |
| `xxx-api.ts` / `api.ts` | 后端调用 | `api/`、feature 内 |
| `xxx-types.ts` / `types.ts` | 类型定义 | `types/`、feature 内 |
| `xxx.test.ts(x)` | 单测 | `__tests__/` 或就地 |
| `*.lazy.tsx` | 路由懒加载分片 | `routes/` |
| `resolveXxx` / `deriveXxx` / `normalizeXxx` | 纯函数 | `lib/`、`domain/` |
| `assertXxx` / `isXxx` | 守卫 | `lib/`、`domain/` |

**「三件套」模式** `[核实]`：编辑器类功能常见 `XxxEditor.tsx`（主体）+ `XxxPanel.tsx`（侧栏参数）+ `XxxDialog.tsx`（模态）三件，共享同一份状态 hook。看到其中一个，另两个大概率在附近目录。

## 18. 本篇的边界

1. **未逐条列出约 700 个 UI 组件**（`features/canvas/ui` 132 + `components/` 187 + 各 feature 内的面板）。原因见 [00 §4](../00-文档地图与覆盖度.md)：大量 30–80 行的浮层逐个描述信息量低、维护成本高于收益，§16 的命名约定可覆盖绝大部分推断需求。
2. **未覆盖样式细节**：`index.css` 的设计令牌、Tailwind 配置、暗色主题变量未展开。
3. **运行时行为**（真实渲染效果、性能数字）需实际跑起来验证，本篇只描述静态结构。
4. **企业版前端**不在本仓库，`features/` 中的 EE 入口以 `[待补]` 标记，无法核实。
