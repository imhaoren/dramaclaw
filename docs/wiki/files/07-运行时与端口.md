# 运行时与端口（81 个）

`ports/`、`ports/local/`、`task_backend/`、`task_backend/runners/`、`shared/`、`security/`、`storage/`。
这是「任务怎么跑、外部能力怎么接」的全部实现。

---

## A. 端口契约（`ports/`，20）

端口是 CE/EE 的移植点：CE 只依赖这里的抽象，`ports/local/` 提供实现，EE 覆盖注册。18 个 EE 必需端口见 [02 §3](../02-架构与分层.md)。

#### `registry.py` · 91 行 `[核实]`

**作用**：进程内端口注册表 + EE 完整性检查。

**接口**：`register_port()`、`get_port()`、`ensure_bootstrap()`；异常 `PortNotRegistered`。
**注意**：`ensure_bootstrap()` 在检测到 `ST_CONTROL_PLANE_DSN` 时校验 18 个端口齐全，缺一个直接 `RuntimeError`，**不降级**。

#### `__init__.py` · 179 行 `[核实]`

**作用**：端口的统一取用入口（`get_auth_port()`、`get_project_registry()`、`get_task_backend()` 等 20+ 个 getter）。

**注意**：业务代码只用这里的 getter，不要直接 `get_port("xxx")`，否则重命名端口会散落各处。

#### `auth.py` / `auth_contract.py` · 42 / 138 行 `[核实]`

**作用**：认证端口（`AuthPort`、`AuthSessionPort`）与跨平面 DTO（`AuthenticatedUser`、`AgentSessionToken`、`ExternalAgentKey`、`LoginResult`、`AuthError`、`AuthFailureReason`）。
**注意**：DTO 是 CE/EE 共享契约，加字段要两端同步；`AuthFailureReason` 决定前端跳转逻辑。

#### `project.py` · 130 行 `[核实]`

**作用**：项目 DTO 与访问端口（`ProjectRecord`、`Principal`、`ProjectRegistry`、`ProjectAccess`）。

**接口**：`role_allows()`、`require_role_value()`。
**注意**：角色层级（viewer < editor < owner）在这里定义，CE 的 `AllowAllProjectAccess` 直接放行，但**角色参数仍会校验**。

#### `tasks.py` · 152 行 `[核实]`

**作用**：任务后端与取消存储端口（`TaskBackend`、`CancellationStore`、`QueuedTask`）。

**接口**：`cancel_key()`、`display_metadata_for_task()`。
**注意**：`cancel_key()` 的格式要与 runner 侧读取一致，否则取消无效。

#### `authz.py` · 224 行 `[核实]`

**作用**：授权与准入契约（`AuthzPort`、`AuthzSnapshot`、`AdmissionContext`、`BillingPrincipal`）。

**接口**：`authz_error_http_status()`、`authz_error_payload()`、`find_authz_error()`、`detach_authz_error()`。
**注意**：错误到 HTTP 状态的映射就在这里，新增错误类型必须加映射，否则退化成 500。

#### `egress.py` / `egress_operations.py` · 75 / 264 行 `[核实]`

**作用**：出网许可与「出网操作账本」（幂等、状态机、未知结果处理）。

**接口**：`EgressPort`、`EgressOperationPort`、`OperationSpec`、`OperationSnapshot`、`canonical_request_digest()`、`record_unknown_outcome()`。
**注意**：`unknown` 是独立状态（可能已执行），不能归入失败。

#### `model_credentials.py` · 58 行 `[核实]`

**作用**：请求级模型凭据契约（凭据引用，不落盘、不进日志）。

**接口**：`RequestCredential`、`CredentialReference`、`ModelCredentialPort`。
**注意**：调试时不要打印 `RequestCredential`，日志脱敏靠 `utils/error_redaction`。

#### `usage.py` · 297 行 `[核实]`

**作用**：计量与 provider 埋点端口（`UsageMeter`、`ProviderInstrumentation`），含结算身份与冲突类型。
**注意**：`FeatureCreditSettlementConflict` 表示同一笔已结算过，重试时要识别它而不是当失败。

#### `credit_quote.py` / `video_delivery.py` / `audit.py` · 33 / 44 / 21 行 `[核实]`

**作用**：三个小端口：报价、网关归档视频取回、审计落库。

**注意**：CE 下分别是 `LocalCreditQuote`、空实现、`NoOpAuditSink`。`ArchivedVideoSource` / `VideoDeliveryReceipt` 是 EE 侧实现的输入输出契约。

#### `release_feed.py` / `lifecycle.py` / `projection.py` · 37 / 12 / 34 行 `[核实]`

**作用**：版本更新源、启停钩子、任务载荷投影三个端口。
**注意**：`TaskProjection` 是"入队时固化项目状态"的机制（见 `task_backend/projection.py`），CE 默认不投影。

#### `canvas_mutex.py` · 70 行 `[核实]`

**作用**：画布写互斥端口；CE 实现就是文件锁。

**接口**：`CanvasWriteMutex`、`CanvasWriteGuard`；异常 `CanvasLeaseLost`。
**注意**：`CanvasLeaseLost` 表示租约过期（写太久），要重新取锁重试，不能继续写。

#### `product_surface_access.py` · 74 行 `[核实]`

**作用**：功能面可见性契约（决定前端显示哪些入口）。
**注意**：CE 的 `LocalProductSurfaceAccess` 默认全开，关功能靠环境变量而非端口。

#### `media_model_catalog.py` · 17 行 `[核实]`

**作用**：媒体模型目录端口（CE 请求处理与 EE 策略共用）。

#### `producer.py` · 193 行 `[核实]`

**作用**：唯一权威的信封生产方（v2）。
**注意**：不要另写签发逻辑，否则验签字段会漂移。
